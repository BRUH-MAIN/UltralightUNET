# UltraLight VM-UNet -- NVIDIA Blackwell (RTX 50-series, sm_120)
#
# The torch 2.0.1+cu117 pinned in ../requirements.txt CANNOT run on a Blackwell
# GPU. Its kernels stop at sm_86 and its only embedded PTX is compute_37, so an
# RTX 5060 (sm_120) fails with:
#     "no kernel image is available for execution on the device"
# PyTorch 2.7.0 was the first stable release shipping native sm_120 CUDA 12.8
# wheels. Notebook cell 1 verifies this empirically by running a real kernel.
#
# Install torch FIRST, from the cu128 index:
#   uv pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
# then:
#   uv pip install -r requirements.txt
#
# torch/torchvision are deliberately unpinned: the cu128 index moves, and
# torchvision declares its own compatible torch version, so letting the resolver
# pick the pair is more robust than a pin that silently goes stale. Known good as
# of 2026-07: torch 2.11.0+cu128 (cp311, win_amd64).
#
# numpy is left loose here (../requirements.txt pins 1.26.4) because newer torch
# builds ship against numpy 2.x. Nothing here is numerically sensitive to it --
# numpy only does the dataset mean/std and the sklearn confusion matrix; all
# training arithmetic is torch.
#
# NOT listed, on purpose: mamba_ssm / causal_conv1d / triton. See ../README.md --
# models/mamba_pytorch.py is a verified pure-PyTorch replacement used on every
# platform, so the code being debugged is the code producing the numbers.
